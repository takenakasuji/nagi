# Nagi（凪）

AI 時代のメモ帳。**雑に書いて、速く貯める**ためのメニューバー常駐アプリ。

1 ファイルずつ丁寧に作るためのエディタではない。ホットキーで窓を出し、思考を止めずに書き、
指定フォルダに `.md` を吐く。整理・リネーム・構造化はあとから Claude Code や Obsidian に任せる。

そのため **アプリ自身に AI は入っていない**。責務は「捕まえて、置く」だけ。

## 使い方

| 操作 | 動作 |
|------|------|
| `⌥Space` | メモ入力ウインドウを開く／閉じる（設定で変更可） |
| `⌘Enter` / `⌘S` | 指定フォルダに `<ファイル名>.md` として保存し、ウインドウを閉じる |
| `⌘⇧S` | 書きかけを退避し、エディタを空にする |
| `Esc` | ウインドウを隠す。**内容は消えず**、次に開くと続きから |
| `Enter`（ファイル名欄） | 本文へ移動（誤って保存しないため） |
| `⌘,` | 設定を開く（ウインドウの歯車ボタンからも） |
| `⌘W` / `Esc`（設定ウインドウ） | 設定を閉じる |

- ファイル名は毎回自分で入力する。`.md` は自動で付き、入力中は薄い文字で後ろに表示される
  （自分で `.md` まで書いた場合は二重に付かないので、表示も消える）。
- 同名ファイルがあれば `名前-2.md` のように連番を付け、**既存を上書きしない**。
- 保存しないメモは何件でも退避でき、一覧から再開・破棄できる。
  破棄した直後なら「元に戻す」で戻せる（退避した下書きはファイルとして存在しないため）。
- 未保存の内容は `~/Library/Application Support/Nagi/state.json` に退避される。
  メモ本体のフォルダは保存した `.md` 以外で汚さない。

## インストール

```bash
./scripts/build-app.sh && cp -R build/Nagi.app /Applications/
```

初回起動時に保存先フォルダを訊かれる。Obsidian の Vault や Claude Code の作業フォルダを指定する。
あとから「設定…」でも変更できる。

メニューバーの風アイコンから「新規メモ」「退避した下書き」「設定…」「終了」。
Dock にはアイコンが出ない（`LSUIElement`）。

## 開発

フル Xcode は不要で、Command Line Tools だけでビルドできる。

```bash
./scripts/test.sh
```

```bash
./scripts/build-app.sh --debug
```

`scripts/test.sh` は swift-testing の `Testing.framework` を探してフラグを補う。
Command Line Tools 環境では `_Testing_Foundation` のモジュールが同梱されていないため、
クロスインポートオーバーレイの自動読み込みも切っている（このオーバーレイの API は使っていない）。

### 構成

責務ごとに 3 つの層に分けてある。副作用は端に寄せ、判断のあるコードは全てテストで固めている。

| ターゲット | 中身 |
|-----------|------|
| `NagiCore` | 純ロジック。AppKit / SwiftUI を知らない |
| `NagiUI` | 画面・パネル・グローバルホットキー・操作の組み立て |
| `Nagi` | `@main` だけ。実体は上の 2 つ |

`NagiCore` の主役:

- `NoteWriter` — `.md` の書き込み。拡張子補完、ファイル名のサニタイズ、衝突時の連番
- `DraftSession` — 保存 / 退避 / 復元の状態遷移。アプリの振る舞いの中心
- `StashStore` — 未保存状態の永続化
- `Draft`, `Preferences`, `Hotkey` — データと設定

`NagiUI` の `AppEnvironment` が操作を `NagiCore` の遷移に変換する。
ウインドウ・ホットキー・フォルダ選択は差し替え可能な形で注入しているので、
モーダルや実ウインドウなしにテストできる。

### テスト

64 件。ファイルは実際にディスクへ書いて検証している。
`Real AppKit integration` スイートだけは実際の `NSPanel` と Carbon の
`RegisterEventHotKey` を叩くのでウインドウサーバが要る。

## メニューバーのアイコンが見えないとき

ノッチ付きの MacBook でメニューバーが埋まっていると、**後から起動したアプリのアイコンは
ノッチの中に押し出されて見えなくなる**。macOS はノッチに何も描かず、あふれた印も出さない。

アイコンは存在していて、機能もしている（`⌥Space` は問題なく効く）。確認するには:

```bash
swift -e 'import AppKit; let s = NSScreen.main!; print("notch x:", s.auxiliaryTopLeftArea!.maxX, "–", s.auxiliaryTopRightArea!.minX)'
```

対処:

- システム設定 → コントロールセンター で使っていない項目を「メニューバーに表示しない」にする（確実）
- アイコンの間隔を詰める（**ログアウトが必要**）:
  ```bash
  defaults -currentHost write -globalDomain NSStatusItemSpacing -int 6
  ```
- Ice（無料）や Bartender などのメニューバー管理アプリを使う
- ノッチのない外部ディスプレイなら、そのまま出る

アイコンに辿り着けなくても Nagi は使える。`⌥Space` で書けて、`⌘,` で設定を開ける。

## 既知の制限

- **ホットキー衝突は検出できないことがある。** macOS は他アプリが同じ組み合わせを
  握っていても登録を成功として返すことがあるため、反応しない場合は設定で別のキーに変える。
- ad-hoc 署名。配布するなら Developer ID での署名と公証が要る。
- 非サンドボックス。保存先はパスとして保存している。App Store 配布を狙うなら
  セキュリティスコープ付きブックマークに変える必要がある。
- 「ログイン時に起動」は署名済みで `/Applications` にある場合に安定して動く。
