AI 時代の、ノートの取り方

きれいに書いてから貯めるのではなく、雑に貯めてから整えてもらう。書く速さと、読める形。その両方を人間が一度にやる必要は、もうない。

Nagi が引き受けるのは、この入り口だけです。整理・リネーム・構造化はあとから Claude Code や Obsidian に任せる。だから、開いた瞬間から書ける。

雑に書いても、失われない

速く書けることと、あとで困らないこと。この 2 つは両立します。

  • ローカルファースト

    通信しない。書いたものは手元のフォルダに .md として置かれるだけで、クラウドにもデータベースにも預けない。オフラインでも書けるし、同期を待つ時間もない。

  • 既存のファイルを上書きしない

    同じ名前のファイルがあれば 名前-2.md のように連番を付けて別ファイルにする。うっかり同じ名前で保存しても、前に書いたものは残る。

  • 書きかけが消えない

    Esc で閉じても内容は残り、次に開くと続きから書ける。保存しないメモは何件でも退避でき、一覧から再開も破棄もできる。

キーボードだけで完結する

マウスに手を伸ばす場面がない。ホットキーは設定で変えられる。

Nagi のキー操作一覧
キー動作
⌥Spaceメモ入力ウインドウを開く／閉じる（設定で変更可）
⌘Enter / ⌘S指定フォルダに ファイル名.md として保存し、ウインドウを閉じる
⌘⇧S書きかけを退避し、エディタを空にする
Escウインドウを隠す。内容は消えず、次に開くと続きから
Enterファイル名欄では本文へ移動する（誤って保存しないため）。本文のリスト行では次の項目を続ける
Tab / ⇧Tab本文のリスト行を入れ子にする／戻す
⌘,設定を開く
⌘W / Esc設定ウインドウを閉じる

インストール

  1. ダウンロードして解凍する

    zip を展開すると Nagi.app が出てきます。Apple Silicon / Intel 共通の universal ビルドです。

  2. Nagi.app を /Applications に入れる

    ここに置いておくと「ログイン時に起動」が安定します（署名していない現状では、それでも外れることがあります）。

  3. 初回だけ、システム設定で開くことを許可する

    Nagi は ad-hoc 署名です。Apple の Developer ID による署名と公証をしていないため、初回はそのままでは起動できません。一度 Nagi.app を開こうとしてから、システム設定 → プライバシーとセキュリティ を開き、下のほうに出る「"Nagi" は開発元を確認できないため、使用がブロックされました」の横の「このまま開く」を押してください。次からは普通に起動します。

    macOS 14 Sonoma では、Nagi.app を右クリック →「開く」でも許可できます。macOS 15 Sequoia 以降はこの方法が使えなくなったため、上の手順を使ってください。

  4. 保存先フォルダを選ぶ

    初回起動時に訊かれます。Obsidian の Vault や Claude Code の作業フォルダを指定してください。あとから設定（⌘,）で変更できます。

ソースからビルドする

フル Xcode は不要で、Command Line Tools だけでビルドできます。

git clone https://github.com/takenakasuji/nagi.git
cd nagi
./scripts/build-app.sh
cp -R build/Nagi.app /Applications/

Homebrew — 準備中。brew install --cask nagi は将来対応します。

うまく動かないときは README に、ホットキーが他のアプリと衝突する場合とメニューバーのアイコンが見えない場合の対処をまとめてあります。
